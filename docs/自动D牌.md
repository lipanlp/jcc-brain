# 自动 D 牌

## 怎么启动

在已配置好的项目环境运行 `jcc gui` 打开 Web 界面。点击顶部「自动 D 牌」（或 `⌘2`），勾选、添加目标英雄并选星级，填写保留金币和最多刷新，点击「开始 D 牌」。未指定目标时会从目标阵容取主副 C、追星卡，或核心卡。

CLI 在项目根目录运行；把「名字」换成当前赛季英雄名，多个目标用空格分开：

```sh
PYTHONPATH=src python -m jccbrain autoroll --target 名字=2 --keep 10 --max-rolls 30 --read-interval-ms 100
```

安装后的命令入口是 `jcc`，可将上例的 `python -m jccbrain` 换成 `jcc`。省略 `--target` 时使用目标阵容；`--read-interval-ms` 只覆盖本次运行，不保存设置。

默认 `actuator.dry_run=true`，演练只记录操作，不点击，也不会推进虚拟对局。**不加 `--live` 会沿用已保存的设置**；之前关闭过演练，应先在「设置 → 操作」打开演练。CLI 加 `--live` 会将本次运行切为真实点击。Web 底栏显示「演练 / ⚠️ 真实」，点击可切换；真实操作前按界面提示完成坐标标定与权限配置。

## 每轮做什么，什么时候停

读画面 → 买还缺的目标卡 → 没有可买的就刷新 → 等新商店再读 → 输出报告。购买后先重读，确认拥有张数增加或金币下降，再继续判断。

报告每次计算单刷命中率；凑齐概率的 600 次模拟在首次、目标缺口变化或距上次模拟满 5 次刷新时重算，其余报告会标注沿用哪次结果。

- 没有目标、手动目标星级无效、目标全部凑齐时停止；凑齐即停是固定行为。
- 再刷新会低于保留金币、达到最多刷新次数时停止。**保留金币只限制刷新，买卡仍可能花到线下**；达到次数上限后仍可买当前商店里的目标卡。
- 离开准备/战斗阶段、商店关闭或急停时停止。Web 工具栏「停止」、`⌘.`、主屏左上角急停均可中止；CLI 可用 `Ctrl+C`。
- 连续 2 批买卡未生效、连续 5 帧读不到金币、连续 3 次刷新未生效时停止，避免反复空点。

## 参数怎么调

在「设置 → 自动D牌 / 操作」调整；下面前五项属于 `autoroll`。范围指运行时有效范围，操作参数另列建议值。

| 参数 | 默认 | 范围 | 什么时候调 |
|---|---:|---|---|
| `keep_gold` | 0 | 0～100 整数 | 想留金币时调高；CLI 用 `--keep`，启动弹窗可覆盖 |
| `target_star` | 2 | 1～3 整数 | 自动目标的默认星级；有效阵容星级优先，手动目标用 `名字=星级` |
| `max_rolls` | 30 | 0～200 整数；Web 启动弹窗 1～200 | 控制本次刷新上限；CLI 用 `--max-rolls`，0 时只可能买当前商店 |
| `buy_pairs_only` | false | true / false | 打开后，尚未持有的目标只在商店同时有至少两张时购买 |
| `read_interval_ms` | 100 ms | 0～1000 整数 | 动画未结束或画面不稳时调大；只在 D 牌期间临时生效，结束恢复原间隔 |
| `actuator.click_delay_ms` | 60 ms | 建议非负整数；设置表单上限 100000 | 真实点击后反馈偏慢时调大；这是点击后的等待，未做 D 牌专用夹紧 |
| `actuator.max_actions_per_sec` | 6.0 | 建议正数；设置表单上限 10000 | 每秒操作限速，通常保留 6；设小会更慢，不要设为 0 |
| `actuator.dry_run` | true | true / false | 演练确认目标和操作记录；准备真实点击时关闭或在 CLI 加 `--live` |

前五项中的数值参数超范围会夹到边界，异常类型回默认值；手动指定的非法星级会直接停止。

## 速度与准确率

终测为 **离线假画面基准**，每次识别固定等待 150 ms，这是识别耗时假设，不是当前实机 OCR 测量。两组各 30 局、seed=1；D 牌读帧间隔 100 ms，点击延迟 60 ms，每秒最多 6 次操作。

| 平均墙钟（ms/刷新） | #1 基线 | 终测 | 下降 |
|---|---:|---:|---:|
| lag 0（无旧帧延迟） | 462.686 | 320.100 | 30.817% |
| lag 1（每次刷新多一帧旧画面） | 871.759 | 573.611 | 34.201% |

两组都刷新 596 次，4 局凑齐、26 局到金币保留线；误买 0、漏买 0、应买 72。该结果验证假画面下的购买决策，不能作为实战识别准确率。

视觉商店识别的历史样本结果见[视觉识别优化报告](vision-optimize.md)「T1 打包适配验证」：27 帧 × 3 遍，商店名字、费用、羁绊、道具和不确定标记均为 100%；只适用于该评测样本。

## 已知限制

- 本次 D 牌优化只在离线假画面验证，尚未做真实对局验收。
- `read_interval_ms` 太小，真实刷新动画可能尚未结束；非道具商店格识别不确定时最多额外读一帧，仍可能不确定，可调大间隔。
- 拥有张数依赖棋盘和备战席识别；漏识别、星级识别错误会影响缺口和购买判断。

## 怎么跑基准

在项目根目录、已配置好的 Python 环境中运行：

```sh
PYTHONPATH=src python scripts/bench_autoroll.py --runs 10 --seed 1
```

这会用本地数据库的副本跑 10 局可复现假对局，不点击游戏；`--seed 1` 固定商店随机序列。默认识别 150 ms、D 牌间隔 100 ms、lag 0；`--lag-frames 1` 模拟刷新后多一帧旧画面，`--json var/result.json` 保存证据。基准使用真实限速和操作等待；后台负载也会影响结果。

重点看总刷新次数、结束原因、误买/漏买/应买及平均耗时。平均耗时 = 总墙钟 / 总刷新次数，包含读取、等待、操作和报告；`read` 次数/刷新可看出是否多读。`_report` 是报告耗时，`pool` 包含在其中，不能重复相加；决策正确性应结合 oracle 指标，不能只看速度。
